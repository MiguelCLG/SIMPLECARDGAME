# SpaceOdyssey

Slay-the-Spire-like card battler with a level-path run. Godot 4.7 (C#/.NET 9), mobile renderer, portrait 360x718. Launch scene: `Scenes/MainMenu.tscn` (Start → New Game/Continue sub-panel, Options, Quit); run map: `Scenes/PathMap.tscn`; gameplay scene: `Scenes/Encounter.tscn` (driven by `GameManager.cs` on the scene root).

## Build & verify
- No linter. `dotnet build` works as a compile sanity check. Tests use gdUnit4Net: `GODOT_BIN=/path/to/Godot_v4.7.1 dotnet test --settings .runsettings` (adapter needs a Godot .NET binary even for pure-logic suites). CI runs tests on PR/push via `.github/workflows/tests.yml`. Run the game from the Godot 4.7(.NET) editor; `GameManager` logic lives in C# attached to the `Encounter.tscn` root.
- `Program.cs` (kept as a valid empty comment-only stub) and `*.uid` files are auto-generated by Godot — never hand-edit beyond the stub (commit `.uid` files, leave content alone). If the engine regenerates `Program.cs` as bare `{}`, `dotnet build` fails with CS8805; restore the comment-only stub. `*.csproj.old*` are stale leftovers (gitignored).
- After adding/removing C# members used by `.tscn`/`.tres` exports, the Godot editor must rescan or reload the project.

## Architecture
- Run flow: `MainMenu` (New Game/Continue) → `PathMap` (pick a node per step, ±1 column adjacency) → `Encounter` → back to `PathMap` until boss row → win/lose ends the run and returns to the menu.
- Run state lives in the static `RunManager.CurrentRun` (a `RunData`); nodes/rows come from `PathGenerator.Generate()` (9 step rows of 3–4 Encounter/Rest nodes + 1 boss row). Rest nodes heal 25% max HP; boss is a single enemy with ×1.5 health; step rows scale enemy health ×(1 + 0.15·row).
- Persistence: `SaveManager` writes one auto-save (`user://savegame.json`, mid-encounter exact state) + a run-history list (`user://runs.json`). Save logic is in `scripts/Run/` (data/hydration classes `CardSaveData`, `EnemySaveData`, `RunManager`). Don't serialize Godot nodes — snapshot plain data via `Player.CollectState()/CollectCards()`, `Enemy.CollectState()`, `CardSaveData.FromCard()`, and restore with `ApplyState`/`SetDeck`/`SetHand`/`SetDiscard`/`SpawnEnemyFromSave`.
- `GameManager.SetupRun()` on `Encounter._Ready` hydrates the run: spawns enemies from `run.Enemies` when `resumedEncounter` (mid-encounter save) else generates fresh scaled enemies and persists. `OnEnemyDie` → `RunManager.CompleteCurrentNode()` + back to `PathMap` (or boss `EndRun(true)`); `OnPlayerDie` → `EndRun(false)`. No more `Restart()`/`StartGame()` — removed.
- Custom event bus, NOT Godot signals: static string-keyed `EventRegistry` + `EventPublisher`/`EventSubscriber`. Every event must be `RegisterEvent`-ed before raise/subscribe; setup lives in `GameManager.RegisterEvents()`. Existing events: `OnCardClick`, `OnEnemyClick`, `OnEnemyDie`, `OnPlayerDie`, `OnEndTurnPress`, `OnEscapeKey`. Failing to register a new event raises a NullReferenceException.
- Card/Player/Enemy UI nodes are Buttons that publish to the bus (`Card.OnButtonPressed`, `Player.OnEndTurnPress`, `Enemy.OnEnemyClick`). Targeting flows through `GameManager` (`selectedCard`).
- Node access uses unique names (`%Player`, `%EnemySpawn`, `%EndTurnButton`, `%HandContainer`, `%PathContainer`, `%RestPanel`, `%GamePanel`, etc.). Renaming a node in a `.tscn` silently breaks `GetNode<T>("%Name")` calls.
- Card effects: add a subclass in `scripts/CardEffect/Effects/` AND a matching string case inside `Card.InitializeEffect()` (switch on `EffectString`: `"Attack"`, `"Defense"`, `"Draw"`, `"Mana"`, `"Cleave"`, `"Poison"`). Forgetting either half = effect silently does nothing.
- Theming: UI styling lives in `Themes/Theme.tres` (shared `default_font`, `StyleBox`es, type variations like `Card`, `MainMenuButton`, `PathNodeButton`, `HealthBar`). When a Control needs custom styling, always prefer adding a **theme type variation** there and referencing it via `theme_type_variation` on the node, instead of adding per-node `theme_override_*` properties, whenever possible.

## Data
- Cards, decks, and enemies are `.tres` Resources (`Resources/Cards/`, `Resources/Decks/`, `Resources/Enemy/`), configured via the Godot inspector. The starter deck is hydrated by `RunManager.NewRun()` from `Resources/Decks/InitialDeck_test.tres`; enemy stats come from the `[Export] Array<EnemyResource>` wired in `Encounter.tscn`.
- The `initialDeck` export on `Encounter.tscn` is now unused by code (live deck comes from the run save) — don't rely on it.
- `Data/*.json` and `GameManager.GetEnemyTypesFromJson()`/commented-out `LoadDeckFromJson` are dead legacy JSON code — don't extend; move data into `.tres` instead.
- `export_presets.cfg` (Web preset) is gitignored; don't commit it.
