# SpaceOdyssey

Slay-the-Spire-like card battler with a level-path run. Godot 4.7 (C#/.NET 9), mobile renderer, portrait 360x718. Launch scene: `Scenes/MainMenu.tscn` (Start → New Game/Continue sub-panel, Options, Quit); run map: `Scenes/PathMap.tscn`; gameplay scene: `Scenes/Encounter.tscn` (driven by `GameManager.cs` on the scene root).

## Build & verify
- No linter. `dotnet build` is the compile sanity check. Run the game from the Godot 4.7(.NET) editor; `GameManager` logic lives in C# attached to the `Encounter.tscn` root.
- `Program.cs` (kept as a valid empty comment-only stub) and `*.uid` files are auto-generated by Godot — never hand-edit beyond the stub (commit `.uid` files, leave content alone). If the engine regenerates `Program.cs` as bare `{}`, `dotnet build` fails with CS8805; restore the comment-only stub. `*.csproj.old*` are stale leftovers (gitignored).
- After adding/removing C# members used by `.tscn`/`.tres` exports, the Godot editor must rescan or reload the project.

## Running the test suite
- gdUnit4Net through the VSTest adapter; suites live in `tests/logic/` (pure logic) and `tests/integration/` (scenes, marked `[RequireGodotRuntime]`). CI runs the whole suite on PR/push via `.github/workflows/tests.yml`.
- It needs a Godot 4.7.x **.NET** (`_mono`) binary — the adapter boots Godot even for pure-logic tests, so a plain (non-.NET) Godot build will not work.
  1. Get `Godot_v4.7.1-stable_mono_win64.zip` from <https://godotengine.org/download/windows/> (or the matching `4.7.1-stable` GitHub release) and extract it. CI uses `chickensoft-games/setup-godot@v2` with `version: '4.7.1', use-dotnet: true`.
  2. Point `GODOT_BIN` at the extracted executable and run from the repo root:
     ```powershell
     $env:GODOT_BIN = "C:\Godot\Godot_v4.7.1-stable_mono_win64\Godot_v4.7.1-stable_mono_win64.exe"
     dotnet test --settings .runsettings
     ```
- Select tests with VSTest filter syntax, e.g. `--filter "FullyQualifiedName~MainMenuNavigationTest"` (or `Namespace=SpaceOdyssey.Tests.Integration`). `Class=<name>` is unreliable here; prefer `FullyQualifiedName~`. Add `--logger "console;verbosity=detailed"` for per-test detail. Results land in `TestResults/test-results.trx`. Note `.runsettings` sets `TreatNoTestsAsError=true`, so a misspelled filter fails loudly instead of passing silently.
- Tests live in the same assembly as game code (`tests/logic/` = pure logic, `tests/integration/` = scene tests; the csproj sets `IsTestProject=true`).
- The csproj sets `RestorePackagesWithLockFile=true` and CI restores with `--locked-mode` against `packages.lock.json` — after adding/bumping any NuGet package, regenerate and commit the lockfile or CI fails.
- The first run imports the project and rebuilds Godot's C# assembly, so it is slow. That step also rewrites `SpaceOdyssey.csproj` (re-pins `Godot.NET.Sdk` to the local editor version) and touches `packages.lock.json` line endings — check `git status` afterwards and don't commit that churn by accident.
- Writing a scene test: `ISceneRunner.Load("res://Scenes/X.tscn", autoFree: true)`, then `await runner.SimulateFrames(count)` or `SimulateFrames(count, msPerFrame)` to drive frames. Tweens advance in real time, so give transitions ≥ ~200 ms (e.g. `SimulateFrames(31, 20)` = 620 ms); trigger UI by emitting the signal, e.g. `node.GetNode<Button>("%StartButton").EmitSignal(BaseButton.SignalName.Pressed)`.

## Architecture
- Run flow: `MainMenu` (New Game/Continue) → `PathMap` (pick a node per step, following that node's explicit outgoing connections) → `Encounter` → back to `PathMap` until boss row → win/lose ends the run and returns to the menu.
- Run state lives in the static `RunManager.CurrentRun` (a `RunData`); nodes/rows come from `PathGenerator.Generate()` (9 step rows of 1–4 Encounter/Rest nodes + 1 boss row). Connectivity is explicit: each `PathNode.Connections` lists the next-row columns it leads to, built by `PathGenerator.BuildConnections()` so every node has ≥1 outgoing edge, every next-row node has ≥1 incoming edge, and every last-step node reaches the boss (out-degree varies: widening rows branch, equal rows stay one-to-one). `RunManager.IsSelectable` follows `Connections` (not ±1 adjacency). Rest nodes heal 25% max HP; boss is a single enemy with ×1.5 health; step rows scale enemy health ×(1 + 0.15·row).
- Persistence: `SaveManager` writes one auto-save (`user://savegame.json`, mid-encounter exact state) + a run-history list (`user://runs.json`). Save logic is in `scripts/Run/` (data/hydration classes `CardSaveData`, `EnemySaveData`, `RunManager`). Don't serialize Godot nodes — snapshot plain data via `Player.CollectState()/CollectCards()`, `Enemy.CollectState()`, `CardSaveData.FromCard()`, and restore with `ApplyState`/`SetDeck`/`SetHand`/`SetDiscard`/`SpawnEnemyFromSave`.
- `GameManager.SetupRun()` on `Encounter._Ready` hydrates the run: spawns enemies from `run.Enemies` when `resumedEncounter` (mid-encounter save) else generates fresh scaled enemies and persists. Encounter end: `OnEnemyDie` → boss row calls `RunManager.EndRun(true)`; otherwise `ShowRewardOrComplete()` offers 3 reward cards via `RewardPanel`/`RewardGenerator` (from the `rewardCardPool` export on `Encounter.tscn`; skip or missing pool falls through immediately) — the node is only completed (`RunManager.CompleteCurrentNode()` → back to `PathMap`) after the player picks or skips. `OnPlayerDie` → `EndRun(false)`. No more `Restart()`/`StartGame()` — removed.
- Custom event bus, NOT Godot signals: static string-keyed `EventRegistry` + `EventPublisher`/`EventSubscriber`. Every event must be `RegisterEvent`-ed before raise/subscribe; setup lives in `GameManager.RegisterEvents()`. Existing events: `OnCardClick`, `OnEnemyClick`, `OnEnemyDie`, `OnPlayerDie`, `OnEndTurnPress`, `OnEscapeKey`. Failing to register a new event raises a NullReferenceException.
- Card/Player/Enemy UI nodes are Buttons that publish to the bus (`Card.OnButtonPressed`, `Player.OnEndTurnPress`, `Enemy.OnEnemyClick`). Targeting flows through `GameManager` (`selectedCard`).
- Node access uses unique names (`%Player`, `%EnemySpawn`, `%EndTurnButton`, `%HandContainer`, `%PathContainer`, `%RestPanel`, `%GamePanel`, etc.). Renaming a node in a `.tscn` silently breaks `GetNode<T>("%Name")` calls.
- Card effects: add a subclass in `scripts/CardEffect/Effects/` AND a matching string case inside `Card.InitializeEffect()` (switch on `EffectString`: `"Attack"`, `"Defense"`, `"Draw"`, `"Mana"`, `"Cleave"`, `"Poison"`). Forgetting either half = effect silently does nothing.
- Theming: UI styling lives in `Themes/Theme.tres` (shared `default_font`, `StyleBox`es, type variations like `Card`, `MainMenuButton`, `PathNodeButton`, `HealthBar`). When a Control needs custom styling, always prefer adding a **theme type variation** there and referencing it via `theme_type_variation` on the node, instead of adding per-node `theme_override_*` properties, whenever possible.

## Data
- Cards, decks, and enemies are `.tres` Resources (`Resources/Cards/`, `Resources/Decks/`, `Resources/Enemy/`), configured via the Godot inspector. The starter deck is hydrated by `RunManager.NewRun()` from `Resources/Decks/InitialDeck_test.tres`; enemy stats come from the `[Export] Array<EnemyResource>` wired in `Encounter.tscn`.
- The `initialDeck` export on `Encounter.tscn` is now unused by code (live deck comes from the run save) — don't rely on it.
- `Data/*.json` and `GameManager.GetEnemyTypesFromJson()`/commented-out `LoadDeckFromJson` are dead legacy JSON code — don't extend; move data into `.tres` instead.
- `export_presets.cfg` (Web preset) is gitignored; don't commit it.
